Foundation: What is a Firewall?

Start Learning

Welcome to Firewall Security!

Imagine your home has doors and windows. You lock them to keep intruders out, right? A firewall does the same thing for your computer network - it's a digital security guard that controls who and what can enter or leave your network.

Real-World Analogy:

Think of a firewall like the security checkpoint at an airport. Just as airport security checks passengers, baggage, and boarding passes before allowing anyone through, a firewall examines every piece of data (called a "packet") trying to enter or leave your network. If the data looks suspicious or doesn't meet the security rules, the firewall blocks it.

Why Do We Need Firewalls?

Every second, your computer or phone connects to countless servers on the internet. Without a firewall, hackers could:

  • Steal Your Data: Bank passwords, credit cards, personal photos, and private messages
  • Install Malware: Viruses, spyware, or ransomware that locks your files until you pay
  • Take Control: Turn your computer into a "zombie" that attacks other systems
  • Monitor Activity: Watch everything you type, including passwords and private conversations
  • Delete Files: Destroy your important documents, photos, and work

How Does a Firewall Work?

A firewall operates based on security "rules" that you configure. These rules are like a bouncer's checklist at a club entrance. Here's what happens:

Step 1: Inspection
Every packet of data is examined. The firewall checks: Where is this coming from? Where is it going? What type of data is this?

Step 2: Rule Matching
The firewall compares the packet against its list of rules. For example, "Allow web browsing (HTTP) but block file sharing programs."

Step 3: Decision
Based on the rules, the firewall decides: ALLOW (let it through) or DENY (block it).

Step 4: Logging
The firewall records what happened so you can review security events later.

Types of Data Packets:

Not all data is the same! Here are common types of network traffic:

  • Web Browsing (HTTP/HTTPS): When you visit websites like Google or Facebook
  • Email (SMTP/IMAP): Sending and receiving emails
  • File Transfer (FTP): Uploading or downloading files to/from servers
  • Remote Access (SSH): Connecting to another computer remotely
  • Video Calls (RTP): Zoom, Skype, FaceTime communications
  • Gaming Traffic: Online multiplayer games

Firewall Rules Examples:

ALLOW: HTTP (port 80) from ANYWHERE → This lets everyone browse websites
ALLOW: HTTPS (port 443) from ANYWHERE → This lets everyone browse secure websites
DENY: SSH (port 22) from EXTERNAL → This blocks remote access from outside
DENY: FTP (port 21) from ANYWHERE → This blocks file transfers for security
ALLOW: Email (port 25) from KNOWN SERVERS → This lets you receive email from trusted servers

Where Are Firewalls Used?

  • Your Computer: Windows Firewall, macOS Firewall
  • Your Router: The box from your internet provider has a built-in firewall
  • Companies: Big corporate firewalls protect entire office networks
  • Websites: Web Application Firewalls (WAF) protect online stores and services
  • Data Centers: Massive firewalls protecting cloud services like AWS and Google Cloud

Understanding Packet Filtering Firewalls

Packet filtering is the oldest and simplest type of firewall technology. It was invented in the late 1980s and is still widely used today because it's fast, efficient, and easy to understand.

What is a Packet?

When you send data over the internet (like loading a webpage or sending an email), your computer doesn't send it all at once. Instead, it breaks the data into small chunks called "packets." Each packet contains:

  • Header: Information about the packet (source, destination, protocol)
  • Payload: The actual data being sent (part of a webpage, email text, etc.)
  • Trailer: Error-checking information to make sure data arrives correctly

What Does a Packet Filter Examine?

A packet filtering firewall looks at the HEADER of each packet (not the content). It checks four main things:

1. Source IP Address
Where is this packet coming from?
Example: 192.168.1.100 (your laptop on your home network)

2. Destination IP Address
Where is this packet going?
Example: 10.0.0.50 (a web server on the internet)

3. Protocol Type
What kind of communication is this?
Examples: HTTP (web), HTTPS (secure web), SSH (remote access), FTP (file transfer)

4. Port Number
Which specific service is being used?
Examples: Port 80 (HTTP), Port 443 (HTTPS), Port 22 (SSH), Port 25 (Email)

Understanding Ports

Think of ports like apartment numbers in a building. The IP address is the building address, and the port number tells you which apartment (service) you're trying to reach:

  • Port 80 (HTTP): Regular web browsing - loading websites
  • Port 443 (HTTPS): Secure web browsing - online banking, shopping
  • Port 22 (SSH): Secure remote access to another computer
  • Port 21 (FTP): File transfer protocol - uploading/downloading files
  • Port 25 (SMTP): Sending emails
  • Port 53 (DNS): Converting website names to IP addresses

How Packet Filtering Works:

Example Scenario: You try to browse to www.google.com

Step 1: Your computer creates packets with:
• Source: 192.168.1.100 (your computer)
• Destination: 142.250.185.46 (Google's server)
• Protocol: HTTP
• Port: 80

Step 2: The packet reaches your firewall

Step 3: Firewall checks its rules:
Rule 1: "ALLOW HTTP (port 80) from ANY to ANY"

Step 4: Packet is ALLOWED through!

Result: Google's webpage loads successfully

Advantages of Packet Filtering:

  • Very Fast: Only checks headers, doesn't inspect packet contents
  • Low Resource Usage: Doesn't require much CPU or memory
  • Simple to Configure: Easy to set up basic rules
  • Widely Supported: Works on almost all routers and devices
  • Transparent: Users don't notice it's there (when working correctly)

Limitations of Packet Filtering:

  • No Content Inspection: Can't see what's INSIDE the packet (could be malware)
  • No User Awareness: Can't tell WHO is making the request
  • No Application Control: Can't distinguish between Netflix and Zoom (both use HTTPS)
  • Easily Spoofed: Hackers can fake source IP addresses
  • No State Tracking: Doesn't remember previous packets (covered in Stateful Inspection)

University Network Example:

A university might configure these packet filtering rules:

ALLOW HTTP (80) from Student Network → Internet
Reason: Students can browse websites for research

ALLOW HTTPS (443) from Student Network → Internet
Reason: Secure browsing for online courses, banking

DENY SSH (22) from Internet → Student Network
Reason: Block hackers trying to remotely access student computers

DENY FTP (21) from Student Network → Internet
Reason: Prevent students from running unauthorized file servers

Next-Generation Firewalls (NGFW)

Next-Generation Firewalls are like upgrading from a basic security guard to an entire security team with specialized skills. While packet filtering firewalls only check "who" and "where," NGFWs ask "what exactly are you doing?" and "are you who you claim to be?"

What Makes NGFWs "Next-Gen"?

NGFWs combine traditional packet filtering with advanced intelligent features:

1. Application Awareness & Control
Unlike basic firewalls that only see "HTTPS traffic on port 443," NGFWs can identify WHICH application is being used. For example:
• Is this Netflix streaming? (High bandwidth, video data)
• Is this Zoom for a video call? (Audio/video, real-time)
• Is this Dropbox syncing files? (File uploads/downloads)
• Is this a web browser or a malicious program pretending to browse?

2. Deep Packet Inspection (DPI)
Goes beyond packet headers and examines the CONTENT inside packets:
• Scans for malware signatures (known virus patterns)
• Detects suspicious commands or code
• Identifies encrypted threats
• Finds data leakage attempts (someone stealing company secrets)

3. User Identity Integration
Knows WHO is making requests, not just which IP address:
• "Allow YouTube for Faculty, block for Students during class hours"
• "Allow remote access for IT staff, deny for everyone else"
• Integrates with Active Directory, LDAP, or other user databases

4. Intrusion Prevention System (IPS)
Actively stops attacks in real-time:
• Blocks known attack patterns (SQL injection, buffer overflow)
• Stops port scanning attempts
• Prevents brute-force password attacks
• Updates attack signatures automatically

5. Threat Intelligence Integration
Connects to cloud databases of known threats:
• Blocks IPs from known botnet command servers
• Identifies zero-day exploits
• Shares threat data across multiple firewalls
• Updates in real-time as new threats emerge

Real-World University Scenario:

The Problem: Students were consuming massive bandwidth streaming Netflix during class, slowing down educational platforms.

Traditional Firewall Limitation:
Can't tell the difference between Netflix (entertainment) and Canvas (learning platform) - both use HTTPS on port 443!

NGFW Solution:
Allow Zoom, Microsoft Teams, Canvas - Educational apps
Block Netflix, Disney+, TikTok during 8am-5pm - Entertainment apps
Allow for Faculty at all times - User-based policies
Limit BitTorrent to 10% bandwidth - Application-level control

How Application Identification Works:

NGFWs use multiple techniques to identify applications:

  • Signature Matching: Recognizes unique patterns in app traffic (Netflix has distinct streaming patterns)
  • Behavioral Analysis: Watches how the app behaves (video calls have different patterns than web browsing)
  • SSL/TLS Inspection: Can decrypt and inspect HTTPS traffic (with proper certificates)
  • Heuristic Analysis: Uses AI/ML to identify unknown or new applications

Advantages vs. Basic Firewalls:

  • Granular Control: Block specific apps, not entire protocols
  • Better Security: Catches threats that simple firewalls miss
  • User Accountability: Know exactly who did what
  • Bandwidth Management: Prioritize critical apps over entertainment
  • Compliance: Meet regulatory requirements (HIPAA, PCI-DSS)

Challenges & Considerations:

  • Expensive: Enterprise NGFWs can cost $10,000 - $100,000+
  • Complex Setup: Requires skilled IT professionals to configure
  • Performance Impact: Deep inspection slows down traffic (less than traditional firewalls)
  • Privacy Concerns: SSL inspection means firewall can see encrypted data
  • False Positives: May block legitimate traffic if misconfigured

Common NGFW Vendors:

Popular enterprise NGFW solutions include: Palo Alto Networks, Cisco Firepower, Fortinet FortiGate, Check Point, and Sophos XG Firewall.

Web Application Firewalls (WAF)

Web Application Firewalls are specialists - they focus ONLY on protecting websites and web applications. Think of a WAF as a bodyguard specifically trained to protect celebrities (your website) from paparazzi and stalkers (hackers).

Why Do Websites Need Special Protection?

Traditional firewalls can't protect against attacks that happen INSIDE legitimate web traffic. When you visit a website, you're using HTTP/HTTPS which is normally allowed. But hackers exploit this:

The Challenge:
• A firewall sees: "HTTPS traffic to port 443" Looks normal!
• Reality: Could be a hacker injecting malicious code into a login form
• Traditional firewall: Can't tell the difference
• WAF: Inspects the web request itself and blocks malicious content

Common Web Attacks WAFs Prevent:

1. SQL Injection (SQLi)
What it is: Hackers insert malicious database commands into web forms
Example Attack: Login form username field:
admin' OR '1'='1 - This tricks the database into logging in without a password!
WAF Protection: Detects SQL syntax in input fields and blocks the request

2. Cross-Site Scripting (XSS)
What it is: Injecting malicious JavaScript into web pages
Example Attack: Comment field on a blog:
<script>steal_cookies();</script>
Impact: Steals user sessions, redirects to phishing sites, modifies page content
WAF Protection: Filters out script tags and malicious code

3. DDoS (Distributed Denial of Service)
What it is: Overwhelming a website with fake traffic to crash it
Example Attack: 100,000 bots send requests simultaneously
Impact: Website becomes slow or completely unavailable
WAF Protection: Identifies bot patterns, rate limits suspicious IPs, challenges users with CAPTCHAs

4. Path Traversal
What it is: Accessing files outside the web directory
Example Attack: URL manipulation:
website.com/download?file=../../../etc/passwd
Impact: Access sensitive system files, passwords, configuration
WAF Protection: Blocks requests with directory traversal patterns

5. Remote File Inclusion (RFI)
What it is: Forcing server to load malicious files from external sources
Impact: Complete server takeover, data theft
WAF Protection: Blocks requests attempting to load external files

How WAFs Work:

Step 1: HTTP Request Interception
WAF sits between users and the web server, intercepting every HTTP request

Step 2: Request Analysis
• Examines URL, headers, cookies, POST data, query parameters
• Compares against attack signature database
• Checks for suspicious patterns and anomalies

Step 3: Decision Making
• Clean request → Forward to web server
• Malicious request → Block and log
• Suspicious request → Challenge with CAPTCHA

Step 4: Response Monitoring
WAF also inspects server responses to prevent data leakage

Real-World Example: Online Banking

Scenario: A bank's online banking website

Attack Attempt #1: SQL Injection on Login
Hacker enters: admin' OR '1'='1 in username field
WAF Action: BLOCKED - SQL syntax detected in login form

Attack Attempt #2: XSS in Money Transfer Note
Hacker tries to inject: <script>alert('hacked')</script>
WAF Action: BLOCKED - Script tags not allowed in form fields

Legitimate User: Normal Login
User enters: [email protected] and password
WAF Action: ALLOWED - Clean, legitimate request

Where WAFs Are Deployed:

  • E-commerce Sites: Amazon, eBay, Shopify stores
  • Banking: Online banking portals, payment processors
  • Social Media: Facebook, Twitter, Instagram
  • SaaS Applications: Google Workspace, Microsoft 365, Salesforce
  • Government: Public-facing government websites

Cloud-Based vs. On-Premise WAFs:

Cloud WAFs (Cloudflare, AWS WAF, Akamai): Easy to deploy, automatic updates, DDoS protection included

On-Premise WAFs (F5, Imperva): More control, better for compliance, higher cost

Key WAF Features:

  • Virtual patching (protect vulnerabilities before code is fixed)
  • Bot detection and management
  • API protection
  • Geo-blocking (block traffic from specific countries)
  • Rate limiting (prevent abuse)
  • SSL/TLS termination and inspection

Stateful Inspection Firewalls

Stateful inspection firewalls add memory to packet filtering. While basic packet filters examine each packet independently (like a security guard with amnesia), stateful firewalls REMEMBER previous packets and understand the context of network conversations.

What Does "Stateful" Mean?

The word "state" refers to the STATUS or CONDITION of a network connection. A stateful firewall maintains a "state table" - a memory of all active connections and their current status.

Connection States:

NEW: Brand new connection attempt
Example: You try to connect to a web server for the first time

ESTABLISHED: Connection is active and ongoing
Example: You're currently viewing a webpage, downloading a file

RELATED: New connection related to an existing one
Example: FTP data transfer related to FTP control connection

INVALID: Packet doesn't belong to any known connection
Example: Random unsolicited packet from unknown source - likely an attack!

How Stateful Inspection Works:

Example: You Browse to www.example.com

Step 1: Outbound Request (NEW)
Your computer: "I want to connect to example.com on port 80"
Firewall: Creates entry in state table:
Connection ID: 12345
Source: 192.168.1.100:54321 (your computer)
Destination: 93.184.216.34:80 (example.com)
Protocol: TCP
State: NEW → ESTABLISHED
Direction: OUTBOUND

Step 2: Return Traffic (ESTABLISHED)
Web server responds with webpage data
Firewall: "Wait, I remember this! Connection ID 12345 is established. This is legitimate return traffic."
Action: ALLOW automatically - no need to check rules again!

Key Insight: Return traffic is AUTOMATICALLY allowed because firewall remembers you initiated the connection. This is huge!

Stateful vs. Stateless Comparison:

Stateless Packet Filter (Old School):
• Examines each packet independently
• No memory of previous packets
• Must configure rules for BOTH directions
• Example rules needed:
  ALLOW Outbound HTTP from Internal → External
  ALLOW Inbound HTTP from External → Internal (for responses)
• Problem: Second rule is a security risk! Hackers can exploit it.

Stateful Firewall (Modern):
• Tracks connection state in memory
• Remembers initiated connections
• Only need one rule:
  ALLOW Outbound HTTP from Internal → External
• Return traffic automatically allowed if connection is ESTABLISHED
• Much more secure! Unsolicited inbound traffic is blocked.

Real-World Security Benefit:

Attack Scenario: Port Scanning
A hacker tries to find open ports on your network by sending packets to random ports.

Stateless Firewall:
Hacker: "Is port 445 open?" (SMB file sharing)
Firewall: "Let me check my rules... no explicit DENY rule for port 445..."
Result: Might accidentally allow or provide information to hacker

Stateful Firewall:
Hacker: "Is port 445 open?"
Firewall: "This packet is INVALID - no established connection for this!"
Result: BLOCKED - No information leaked to hacker

The State Table:

The firewall maintains an in-memory table of all active connections. Here's what a real state table entry looks like:

Connection 1:
Protocol: TCP
Source: 192.168.1.50:49234 → Dest: 172.217.164.142:443
State: ESTABLISHED
Timeout: 3600 seconds
Bytes In: 45KB | Bytes Out: 2.3MB

Connection 2:
Protocol: UDP
Source: 192.168.1.75:5060 → Dest: 198.51.100.20:5060
State: NEW
Timeout: 30 seconds
Bytes In: 512B | Bytes Out: 256B

Connection Timeouts:

Stateful firewalls use timeouts to clean up old connections:

  • TCP ESTABLISHED: 3600 seconds (1 hour)
  • UDP: 30-60 seconds (no formal connection state)
  • ICMP: 10 seconds (ping requests)
  • Half-Open TCP: 30 seconds (incomplete handshake)

If no traffic is seen within the timeout, the connection is removed from the state table.

Security Benefits:

  • Prevents Spoofing: Can't fake a response to a non-existent request
  • Blocks Unsolicited Traffic: Only allows traffic for established connections
  • DoS Protection: Limits number of simultaneous connections
  • Better Logging: Can track entire conversation, not just individual packets
  • Simpler Rules: Fewer rules needed compared to stateless firewalls

Common Protocols & State Tracking:

TCP (Transmission Control Protocol): Easy to track - has formal connection states (SYN, ACK, FIN)
UDP (User Datagram Protocol): Harder to track - connectionless, firewall creates "pseudo-states"
ICMP (Ping): Request/Reply pairs are tracked

Resource Considerations:

State tables require memory. A busy firewall might track millions of simultaneous connections. Enterprise firewalls have dedicated RAM for state table storage.
